# 图片局部擦除 Demo

一个本地 NestJS 服务，使用 MobileSAM 点选分割、LaMa 修复选区。模型由同一 Node.js 进程的常驻 Worker 加载，以 CPU 执行。启动后只监听本机回环地址。

需要 Node.js 22 或更新版本。下载以下三个公开模型文件，将它们放到对应位置。总大小约 253 MB，固定版本、文件大小和 SHA-256 见 [模型清单](models/manifest.json)。

| 下载 | 项目内位置 |
| --- | --- |
| [MobileSAM 图像编码器](https://huggingface.co/Acly/MobileSAM/resolve/0d3b403339b4674a82493d5e97964dd78089ddc8/mobile_sam_image_encoder.onnx) | `models/mobilesam/mobile_sam_image_encoder.onnx` |
| [MobileSAM 分割解码器](https://huggingface.co/Acly/MobileSAM/resolve/0d3b403339b4674a82493d5e97964dd78089ddc8/sam_mask_decoder_multi.onnx) | `models/mobilesam/sam_mask_decoder_multi.onnx` |
| [LaMa FP32 擦除模型](https://huggingface.co/Carve/LaMa-ONNX/resolve/c3c0c9e468934d62e79c329e35d82dd09ff8c444/lama_fp32.onnx) | `models/lama/lama_fp32.onnx` |

准备好模型后，在项目根目录安装依赖并启动。

```sh
npm ci
npm start
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。如端口被占用，可用 `PORT=3001 npm start`。

1. 上传一张单帧 JPEG 或 PNG，点击要移除的物体。切换到「背景」后点击要保留的区域，可以继续修正选区。也可选择「画笔」后按住鼠标涂抹，用「橡皮」减去多选区域。点击「应用手绘」可查看面积，直接点击「擦除选区」也会应用笔迹。
2. 查看叠加的绿色 mask、像素面积及原图占比。也可导入与方向校正后原图同尺寸的单通道 8 位 PNG，纯白表示擦除。
3. 点击「擦除选区」，观察任务进度。完成后切换原图和结果进行对比，并下载结果 PNG。

图片限制为上传 32 MiB、最长边 7680 px、总像素不超过 33,177,600。最长边超过 4096 px 的图片标记为大图。透明图片会先铺白底。擦除范围最多占原图的 50%。大图使用整图缩放分割，8K 小目标选区的精度受模型输入尺寸影响。擦除时按 mask 裁剪局部区域送入 512×512 的 LaMa。推理时扩张遮罩以减少物体轮廓被重新生成，合成时仅修改用户选区。真实照片测试中，复杂背景上的人物轮廓和选区外阴影仍可能残留。大选区降采样后可能丢失细节。

上传、分割、mask 导入和擦除共用一个队列，同一时间执行一个任务。排队中的分割优先执行。取消运行中的任务会等当前计算结束，再丢弃结果。任务状态和 embedding 缓存在内存中，服务重启会清空状态。每次运行的图片文件保存在 `.poc-data/run-*`，可在服务停止后按需清理。

服务运行时，在另一个终端验证：

```sh
npm run verify
```

脚本使用一张 960×640 和一张 7680×4320 合成样本，检查分割、点击缓存复用、mask 面积与错误处理、任务取消与优先级、原尺寸和选区外 RGB 像素。小图的原图、mask 和结果会保存到 `.poc-data/verification/`。使用其他端口时设置 `BASE_URL`。

| 本机 macOS ARM64 CPU，一次测试 | 960×640 | 7680×4320 |
| --- | ---: | ---: |
| 首次编码（含模型输入准备） | 1006 ms | 755 ms |
| 缓存命中后的分割任务 | 64 ms | 194 ms |
| 擦除任务（含前后处理） | 4.17 s | 4.23 s |
| 擦除期间进程 RSS 采样峰值 | 900 MiB | 1087 MiB |
| 选区外不同像素 | 0 | 0 |

这些是固定样本的单次结果，8K 样本修复的是局部小目标。耗时受选区及图片内容影响。

## 脱敏复测报告

2026-11-26 在 macOS ARM64 上使用 CPU 复测，运行环境为 Node.js 22.16.0 和 ONNX Runtime Node 1.23.2。补测使用 5 张此前未参与评测的公开标注照片，统一编号 S01 至 S05。每张图固定一个前景点击坐标，并用同一份人工标注 mask 做擦除对照。每轮启动独立的 NestJS 进程，重新上传全部输入，并轮换测试顺序。共 3 轮，每轮 5 张。精度和视觉通过率均以 5 张独立图片为分母。

### 分割精度与擦除观感

IoU 衡量模型选区和人工标注的重合程度，越接近 1 越准确。本批单点分割 **2/5 张达到 IoU ≥ 0.8**，平均 **0.577**。此前另有 12 张真实照片的测试，单点为 **5/12**，由脚本参照标注模拟补点后为 **11/12**。补点成绩仍需用真人操作验证。

视觉验收对照原图和局部细节，要求目标清除、邻近内容完整、边缘与背景纹理自然。目标主体已经处理但仍有可见轮廓、接缝或结构异常，记为「需修正」。明显漏擦或误擦无关内容，记为「失败」。以下为单人目视评估。

| 样本 | 单点 IoU | 单点 mask 擦除 | 人工标注 mask 擦除 |
| --- | ---: | --- | --- |
| S01 | 0.449 | 失败，误擦邻近内容 | 需修正，保留了邻近主体，但边缘有残留 |
| S02 | 0.974 | 需修正，贴边轮廓和暗块明显 | 需修正，仍有类似轮廓和暗块 |
| S03 | 0.942 | 需修正，轮廓及背景横线有接缝 | 需修正，背景较完整，细边仍可见 |
| S04 | 0.382 | 失败，只去掉目标的一部分 | 需修正，主体填补后局部结构模糊 |
| S05 | 0.136 | 失败，小目标连同邻近主体一起被选中 | 需修正，保留了邻近主体，细线仍可见 |

按上述标准，两种 mask 各有 **0/5 张可直接交付**。人工标注 mask 让这批样本中的 3 个漏擦或误擦案例进入「需修正」，但贴边和复杂纹理仍可能残留。这组小样本用于定位失败场景，业务通过率需另行测量。

### 输出一致性与耗时

三轮共完成 15 次首次分割和 30 次擦除，本批未记录到任务失败。对每张图的三种输出分别跨轮两两比较，共 **45 次比较，变化像素均为 0**，对应 PNG 文件的 SHA-256 也一致。30 次擦除的输出尺寸均与原图一致，选区外 RGB 变化像素均为 0。加上此前不同的 5 张图的三轮测试，两批共完成 90 次跨轮比较，变化像素均为 0。本机 CPU、固定输入和模型版本下未观察到输出随机性。

| 任务 | 次数 | 执行时间中位数 | 执行时间范围 |
| --- | ---: | ---: | ---: |
| 首次点选分割，含图像编码 | 15 | 1.50 s | 0.77–3.18 s |
| 单点 mask 擦除 | 15 | 9.51 s | 5.49–23.63 s |
| 固定人工 mask 擦除 | 15 | 9.41 s | 4.71–17.12 s |

耗时为本机服务端串行任务的执行时间，擦除期间进程 RSS 的最高采样值为 891 MiB。此前批次曾出现客户端取结果失败、模型加载退出和更长的耗时。两批结果支持本地推理链路可行，同时表明单点选区精度和擦除观感仍需改进。正式验收需使用目标机器和业务样本测量画面通过率及混合任务延迟。
